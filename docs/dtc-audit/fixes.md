## 验证与运行范围

### 第二轮：低优先级边界补齐

依据 [官方证券定义](https://www.sierrachart.com/index.php?page=doc/DTCMessages_SymbolDiscoverySecurityDefinitionsMessages.php)、[官方历史响应](https://www.sierrachart.com/index.php?page=doc/DTCMessages_HistoricalPriceDataMessages.php) 和本目录官方头文件，再次核对后补充：

- 旧布局不完整的多字节尾字段和固定字符串整体使用默认值，避免把半个 MaxDays、TimeInForce 或账号误读成有效输入；保留原始 wire Size。完整字段仍按原值处理。
- SecurityExpirationDate 映射上游到期日，ExchangeSymbol 优先使用上游原始符号；到期日仅接受经过校验的 YYYYMMDD/ YYYY-MM-DD，未识别格式保持 0。不根据合约代码猜测到期日或换月日。
- 上游缺少 currency/point_value 时不再编造 USD、合约点值 1 和对应 tick value。备用 underlying 查询清理具体到期合约的价格/币种/到期等元数据，正常根定义也清理 ExchangeSymbol 和到期日。
- 历史流保留最后一条真实记录，直到下一批/结束到达；空末批将最后真实记录标记 IsFinalRecord，跳过空中间批，不发送第二个 header 或虚构交易。TCP 回归验证随后第二个请求仍可完成。代价是最多一条记录延迟到下一批返回。
- 未提供 Start、MaxDays 大于从 Unix 起点至 End 的天数时，查询起点收敛到上游支持的最早正时间，不再因计算出负起点而拒绝有效请求。

新增 4 个回归测试，并扩充日期与 MaxDays 边界断言。仍未实现的内容包括定义变更订阅推送、全部可选元数据和日统计字段，以及慢业务期间完整的行情/交易事件并发调度；没有把这些标成“已全部符合协议”。

执行离线格式检查、完整默认测试及编译；独立输出目录为 `target/dtc-audit`，避免覆盖正在运行的服务器文件。回归包含真实 localhost TCP 分包/心跳、旧消息兼容、慢目录请求、长历史下载，以及模拟上游的订单拒绝、父单拦截、行情/深度单次快照、跨合约枚举和统计字段合并。

最新第二轮结果：`cargo test --target-dir target/dtc-audit` 共 **71 项通过、0 项失败、16 项账户集成测试忽略**（第一轮为 67 项通过）。使用 `cargo fmt --check`、`cargo build --target-dir target/dtc-audit` 和 `git diff --check` 检查格式、构建及差异。新服务器位于 `target/dtc-audit/debug/dtc_server.exe`。

本轮没有连接真实 Rithmic、没有发出真实或 Paper 订单、没有重启当前服务。依赖真实账户的忽略测试不在本轮验证范围；新增上游统计和枚举仍需连接测试确认权限、完整性和性能。替换或重启服务后新源码才会生效。

这些修改修复已发现的具体兼容问题，并扩充行情功能；仍是明确受限的 DTC Binary 实现，不是完整协议认证。
